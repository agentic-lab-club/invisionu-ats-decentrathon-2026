## Переменные окружения

Создайте файл `.env.local` в корне проекта:

```env
# URL бэкенда (Go-сервис)
NEXT_PUBLIC_API_URL=http://localhost:8080
```

> **Важно:** если бэкенд запущен не на `localhost:8080`, укажите корректный адрес и порт.

## Установка и локальный запуск

```bash
# 1. Клонируйте репозиторий и перейдите в папку фронтенда
git clone <repo-url>
cd frontend

# 2. Установите зависимости
npm install
# или: yarn install / pnpm install

# 3. Запустите сервер разработки
npm run dev
# или: yarn dev
```

Откройте [http://localhost:3000](http://localhost:3000) в браузере.

## Сборка для production

```bash
npm run build
npm start
```

Приложение будет доступно на порту `3000`.

## Запуск через Docker

Проект состоит из двух независимых частей:

- **Frontend** (Next.js) — этот репозиторий.
- **Backend** (Go) — [отдельный репозиторий](https://github.com/agentic-lab-club/invisionu-ats-decentrathon-2026).

### Локальная разработка (только фронтенд + PostgreSQL)

Если нужно запустить только фронтенд с собственной базой данных:

```bash
# 1. Запустите базу данных и Next.js
docker-compose up --build

# 2. Примените миграции (создание таблиц)
docker exec invision_app npm run migrate

# 3. Заполните базу тестовыми данными (опционально)
docker exec invision_db psql -U invision_user -d invision_db -f /path/to/seed.sql
```

Фронтенд будет доступен на [http://localhost:3000](http://localhost:3000), база данных — на порту `5432`.

> **Важно:** этот способ не запускает Go-бэкенд. Для работы таблицы кандидатов, отправки заявок и получения данных через API необходимо запустить бэкенд отдельно (см. ниже).

### Полный запуск (фронтенд + бэкенд + БД)

Рекомендуемый способ для полноценной работы:

**1. Запустите бэкенд** (следуя инструкциям в его `README.md`):

```bash
cd backend
docker-compose up --build
```

Бэкенд будет доступен на `http://localhost:8080`.

**2. Запустите фронтенд** (этот репозиторий):

```bash
docker-compose up --build
```

Убедитесь, что в `.env.local` (или в `environment` в `docker-compose.yml`) указан правильный адрес бэкенда:

```env
NEXT_PUBLIC_API_URL=http://localhost:8080
```

**3.** Примените миграции для базы данных бэкенда (если они не применяются автоматически).

**4.** Откройте [http://localhost:3000](http://localhost:3000) для фронтенда и [http://localhost:8080](http://localhost:8080) для API.

### Единый Docker Compose (опционально)

Если нужно управлять всеми сервисами из одного файла — создайте общий `docker-compose.yml`, объединив сервисы из обоих репозиториев. Пример файла можно найти в корне проекта или запросить у команды.

```

├── (dashboard)/          # Страницы дашборда (с навигацией)
```

## Важные замечания

- **Бэкенд запускается отдельно.** Перейдите в папку `backend/` и следуйте инструкциям в её `README.md`.
- Переменная `NEXT_PUBLIC_API_URL` должна указывать на корректный адрес бэкенда:
  - Локальный запуск: `http://localhost:8080`
  - Внутри Docker-сети: `http://backend:8080`
